# @raypx-kit/codemods

A small source migration runner and CLI scaffold for Raypx Kit. **No built-in
migrations are registered yet.** The package provides the execution and test
structure for future API migrations; installing or importing it changes no files.

ESM; Node 22.21+ or Bun. No runtime dependencies. Node TypeScript consumers need
Node types for the runtime environment.

## Install and inspect

```sh
bun add --dev @raypx-kit/codemods
raypx-kit-codemod --help
raypx-kit-codemod list
```

The binary is `raypx-kit-codemod`. `list` currently reports an empty registry;
unknown migration names return a nonzero exit code.

When a named migration is available, pass explicit filenames:

```sh
raypx-kit-codemod <migration> src/config.ts src/feature.ts --dry-run
raypx-kit-codemod <migration> src/config.ts src/feature.ts --write
```

Dry-run is the default and reports `changed` or `unchanged` for each absolute
path without writing. `--write` applies changed files; the two flags cannot be
combined. Use `--` before filenames that begin with a dash. There is no directory
discovery or glob expansion; directories and symlink files are rejected. Output
contains statuses and paths, never source contents.

## Run a custom migration

```ts
import { runCodemod, type Codemod } from "@raypx-kit/codemods";

const migration: Codemod = {
  name: "update-header",
  description: "Update an exact, application-owned file header",
  transform({ source }) {
    // An exact text change; use a parser for syntax-aware migrations.
    const previous = "// generated by old-tool\n";
    if (!source.startsWith(previous)) return null;
    return "// generated by new-tool\n" + source.slice(previous.length);
  },
};

const preview = await runCodemod(migration, ["src/config.ts"]);
console.log(preview);
// Explicit application after reviewing the preview:
await runCodemod(migration, ["src/config.ts"], { write: true });
```

`transform` receives `{ path, source }`, where `path` is absolute and `source` is
UTF-8 text. It may return source text, `null` or `undefined`, synchronously or
asynchronously. A skipped file or identical text is `unchanged`; an empty string
is a valid replacement. Relative paths resolve against `options.cwd` or the
process working directory. Duplicate resolved paths run once, in input order.

`runCodemod` returns `{ mode: "dry-run" | "write", files: [{ path, status }] }`.
All reads and transforms complete before the first write, so a transform error
leaves all input files untouched. Filesystem write failures can leave preceding
changes applied; there is no rollback or repository management. Keep migrations
repeatable and inspect the diff in version control before committing.

## Add a built-in migration

1. Add `src/migrations/<name>.ts` exporting an object satisfying `Codemod`, with a
   stable name, description and transform. Pick a parser only if the migration
   needs it; avoid text replacement for arbitrary language syntax.
2. Add tests under `tests/migrations/` with real before/after examples, preserved
   comments and directives, unsupported syntax, and a second run that produces
   no further changes.
3. Import and register the migration in `src/migrations/index.ts`.
4. Document the affected versions and exact invocation, including preview and
   write examples. Extend the archive consumer when adding parser dependencies
   or runtime requirements.

From this repository, use the source CLI without building first:

```sh
bun run codemod list
bun run codemod --help
bun run --cwd packages/codemods test
bun run --cwd packages/codemods check
bun run build --filter=@raypx-kit/codemods
bun run pack:check
```

Runner tests cover preview, writes, skipped files, path deduplication and failure
before writes. CLI tests inject a test-only migration into the internal registry
interface; they do not ship fake migrations. Archive consumers load the public
API and execute the installed CLI with both Bun and Node.
